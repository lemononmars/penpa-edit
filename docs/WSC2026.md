# WSC 2026 practice room

Open `/wsc2026/`. The supplied v1 booklet (16 September 2026) contains 95 entries across 11 documented rounds. Team rounds 8, 9, 13, 14 and 15 appear only in the schedule. Physical PDF page numbers differ from printed page numbers after page 25. Round 16 lists all playoff choices, whose combined points exceed the maximum 450-point individual playoff path.

## Database setup

Apply `supabase/migrations/20260918000000_wsc2026_practice.sql`, then `supabase/migrations/20260919000000_wsc2026_single_team.sql` using your Supabase SQL editor or your normal migration deployment workflow. The existing `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` are reused. No service-role key belongs in the browser. This task implements and locally tests the migration; it does not deploy it to the live project.

- `wsc2026_rounds`: all 16 round identities, time limits and availability.
- `wsc2026_booklet_entries`: the 95 stable booklet references, round, variant and points.
- `wsc2026_groups`: group identity and private invite capability.
- `wsc2026_members`: case-insensitive group usernames and private random device credentials; maximum five members, enforced under a group row lock.
- `wsc2026_puzzles`: group-owned practice titles, rounds, variant IDs, rules, play links and printable images (PNG/JPEG/WebP, 3 MB per upload). Images are stored inline for this small-group workflow.
- `wsc2026_attempts`: member-owned name, elapsed seconds, solved/DNF/error outcome, notes and date.
- `wsc2026_plans`: per-member, per-puzzle choices with round membership.

The sole private-data API is `wsc2026_api(action, token, payload)`. All private tables use RLS and deny direct browser reads/writes. RPCs scope access using the random device key; a username or group invite does not authorize reading someone else's attempts or plans. New member claims are serialized by locking the group row. Puzzle references are checked against either the booklet catalog or that member's group puzzles. All data from other members is excluded from the private record response.

A username is chosen once. localStorage remembers the device key and username. Download the private backup to restore on another browser: paste its deviceKey into Restore profile. Losing both browser storage and backup loses access; username-only recovery is deliberately not allowed. Sign-out clears the browser session. The single-team migration removes create/join-group choices: new usernames automatically join the same five-member team. Existing device keys remain valid. If multiple groups already exist, the migration stops for an administrator to select the intended team without discarding records. Shared data refreshes after mutations, browser focus and reload.

## Solver coverage

31 WSC rule descriptors were added/promoted through the existing normalized-evidence registry and JavaScript CSP. Seven Hundred combinations compose the existing rules with Hundred sums. Existing equivalent variants retain their IDs. Escape (WSC 2026) has a separate ID from the older descending-path Escape rule. All WSC types are tagged `wsc2026`, categorized by input type and listed in the variant catalog. Samurai, Expanded and Star open a dedicated explicit-topology solver from the dropdown and catalog; they are not passed to the square-grid parser.

Normal clue marks are supported for shaded Hundred runs, cages, line paths (styles 3/5), parity/group circles, numeric divisor edges, transparent Kropki circles and outside numbers. Complex shapes can be specified through the persistent WSC clue editor. See `/wsc2026/clue-guide.html` for exact payloads. Clues live in `pu_q.wsc2026Clues` and therefore travel with saved Penpa links. Missing or malformed required clues produce diagnostics instead of silently solving a Classic puzzle.

The layout solver accepts values, all-different units, optional mapped 9x9 component rules, and cross-grid clone pairs. A Samurai topology template deduplicates the 369 overlapping cells. Authors must enter givens, every relevant unit and all variant clues; it does not transcribe images. It reports unique/multiple/unsatisfiable/invalid/limit and runs in a cancellable worker. Search limits are not uniqueness claims.

Examples are faithful raster extracts, not transcribed playable puzzles. The PDF and extracted examples preserve the booklet's attribution and non-commercial-use restriction. Uploaded practice puzzles may include a play link and a separate solution image. Printing uses the browser's Print / Save as PDF dialog, with solutions omitted. Personal checklists also export CSV; private records and restore credentials export JSON.

## Verification

- `node --test test/sudoku_solver.test.js test/wsc2026.test.js test/wsc2026_database.test.mjs`
- `node test/wsc2026_edge_browser.mjs` for actual edge pointer/keyboard entry.
- `node test/wsc2026_browser.mjs` while the dev server runs at `http://127.0.0.1:5174`, or set `WSC_BASE_URL`.

The database tests run the real migration in PGlite PostgreSQL and test five-member limits, private data isolation, cross-group rejection, restore credentials and invalid input. The browser test routes the app's RPCs to an isolated local PostgreSQL database, covering actual forms and persistence without creating data in the live project. Regenerate source images with `python scripts/extract-wsc2026.py` (PyMuPDF and Pillow required). The checked-in catalog retains its variant mappings during regeneration. The source booklet is required.

## Athlete preparation ideas

Prioritize points-per-minute by variant using clean-solve medians; official-duration mock rounds with a checking reserve; a stall/error log; spaced review of weak variants; stop-loss times and planned solve order; and team handoff/transfer drills. The Training ideas tab describes these extensions. Current timing is self-reported, not an official scoring or anti-cheat system.

## Entry screen and layout

The password `กู้ชาติ` is remembered in `wsc2026-password` localStorage. All WSC app tabs (including direct solver links) render only after the password matches. Shared database RPCs require the password in addition to the private device credential. Vercel routing middleware also protects direct PDF, image and guide requests with an HttpOnly access cookie issued after checking the password. The Vite development and preview servers use the same guard. A plain static file host must supply an equivalent server guard; do not deploy only the dist folder to an unprotected static host.

The first page groups cards by round, keeps the round/search filters, collapses rules, and lists official examples first. Uploaded puzzles match cards by round and variant; unmatched variants get their own card. Saved Penpa/Sudotoku payload links open the main player in a new tab. Printable packs include uploaded puzzles; private records and the printable round checklist remain separate tabs.
